# Work Hour Pace Calculator

## User-visible outcome

사용자가 이번 정산기간의 정상근무시간(목표), 누적근무시간(시간·분), 남은 근무 일수를 입력하고, 앞으로 일할 계획을 "예상 근무 계획"(시간·분·일수 단위 항목 여러 개)과 앞으로 쓸 휴가 계획인 "예상 근무 제외"(전일(8H)/반일(4H)/반반일(2H) 일수)로 입력하면, 계산하기 버튼 없이 값을 입력하는 즉시 그 계획대로 진행했을 때 (휴가만큼 줄어든) 목표를 초과하는지·정확히 충족하는지·부족한지를 계산해서 알려준다. 결과는 판정별로 색이 다른 카드에 굵은 제목과 불릿 목록(총예상근무시간·예상 근무 제외·목표 대비 차이·정상근무시간에 정확히 맞추기 위한 제안)으로 표시된다. 예상 근무 계획의 총 일수가 남은 근무 일수보다 많으면 별도로 경고한다. 입력한 예상 근무 계획과 예상 근무 제외 값은 저장되어, 다음에 웹페이지를 열었을 때도 그대로 남아 있다. 화면 상단에는 오늘 날짜 기준 이번 정산기간(근태일정)을, 하단에는 그 기간 내에 있는 대한민국 공휴일과 사용자가 직접 추가한 휴일을 합쳐서(근태일 기준 공휴일) 참고용으로 보여준다. 사용자는 "+ 휴일 추가" 버튼으로 팝업을 열어 이름·반복 여부(반복 안함/매년 반복)·날짜를 입력해 자신만의 휴일을 추가할 수 있고, 추가한 휴일은 저장되어 다음에 열어도 남아 있으며 언제든 삭제할 수 있다.

## Scope

- 포함:
  - 정상근무시간(시간)·누적근무시간(시간·분)·남은 근무 일수(일) 수동 입력
  - "예상 근무 계획" 여러 항목(시간·분·일수) 입력, 추가·삭제
  - "예상 근무 제외" 입력 — 전일(8H)/반일(4H)/반반일(2H) 일수를 각각 하나씩 직접 입력 (목록 추가·삭제 없음) — 목표(정상근무시간)에서 차감
  - 계획·제외 값들의 합계를 반영한 결과(초과 예상/충족 예상/부족 예상)를 입력 즉시 자동으로 계산·표시 (계산 버튼 없음)
  - 결과를 판정별로 색이 다른 카드 + 굵은 제목 + 불릿 목록으로 표시하고, 정상근무시간에 정확히 맞추려면 예상 근무 계획을 얼마나 조정해야 하는지 제안
  - 예상 근무 계획의 총 일수가 남은 근무 일수를 넘으면 경고 표시
  - 예상 근무 계획·예상 근무 제외 값의 브라우저 저장(localStorage) 및 재방문 시 자동 복원
  - 화면 상단에 오늘 날짜 기준 이번 정산기간(근태일정)을 표시
  - 화면 하단에 근태일정 기간 내에 있는 대한민국 공휴일("근태일 기준 공휴일")을 순수 참고 정보로 표시 (계산에 관여하지 않음)
  - "+ 휴일 추가" 버튼으로 팝업(대화상자)을 열어 이름·반복 여부(반복 안함/매년 반복)·날짜를 입력해 사용자 정의 휴일을 추가. 반복 안함은 특정 연-월-일 1회, 매년 반복은 월-일만 지정해 매년 적용. 추가한 휴일은 브라우저에 저장되어 재방문 시 그대로 복원되며, 근태일 기준 공휴일 목록에 대한민국 공휴일과 함께 날짜순으로 병합되어 표시되고 개별 삭제 가능
- 제외: 근태 화면 캡처 업로드·자동 인식, attendance.lge.com 자동 접속·연동, 로그인/인증, 서버 측 사용자별 데이터 저장.
- 대체됨: 남은근무일수를 단일 숫자로 직접 입력하던 기존 방식과, 이에 기반한 "정상 진행 중"/"부족 위험"(하루 평균 추천) 판정은 예상 근무 계획 기반의 직접 판정으로 대체되었다. 이후 "남은 근무 일수" 입력이 다시 추가되었지만, 용도가 다르다 — 계산의 직접 입력이 아니라 예상 근무 계획의 총 일수와 대조해 경고를 주는 참고값이다.
- 다시 제외됨: 근태 화면 캡처 업로드 자동 인식(서버 API + vision 모델 연동)은 한 차례 구현했으나, 사용자가 이 기능 자체를 삭제하기로 결정해 관련 서버 라우트·클라이언트 코드를 모두 제거했다.
- 입력 방식이 바뀜: 누적근무시간은 하나의 소수 대신 시간·분 두 필드로 입력한다(실제 근태 화면 표기와 동일한 형식). 모든 수치 입력 필드는 비어 있으면 오류가 아니라 0으로 취급하며, "계산하기" 버튼 없이 값이 바뀔 때마다 결과가 자동으로 갱신된다. 남은 근무 일수는 오늘 날짜·근태일정·공휴일 데이터를 이용해 자동으로 기본값이 채워지며(주말·공휴일 제외), 예상 근무 계획·예상 근무 제외 제목 옆에 각각의 합계(총예상근무시간은 시간:분 형식과 총 일수를 함께, 총제외시간은 "N시간")를 표시한다.

## Inputs

- 정상근무시간(시간): 이번 정산기간의 목표 총 근무시간 (소수점 허용, 0 이상, 저장하지 않음). 비어 있으면 0으로 취급한다.
- 누적근무시간(시간): 현재까지 실제로 일한 시간을 "시간"·"분" 두 필드로 입력한다(정수, 0 이상, 저장하지 않음). 계산 시 시간 + 분÷60으로 환산한다. 각 필드가 비어 있으면 0으로 취급한다.
- 남은 근무 일수(일): 정산기간 종료일까지 남은 실제 근무 일수 (정수, 0 이상, 저장하지 않음). 오늘 날짜와 근태일정(정산기간 종료일)을 기준으로 공휴일·토요일·일요일을 제외하고 자동으로 계산되어 기본값으로 채워지며, 사용자가 필요하면 직접 수정할 수 있다. 비어 있으면 예상 근무 계획 총 일수 경고를 계산하지 않는다("Calculation and judgment" 참고).
- 예상 근무 계획: 0개 이상의 항목 목록. 각 항목은 시간(정수, 0 이상) · 분(정수, 0 이상) · 일수(정수, 0 이상)로 구성되며, "이 시간만큼 일하는 날이 이 일수만큼 있다"를 의미한다. "+ 추가"로 항목을 늘리고 각 항목을 개별적으로 삭제할 수 있다. 브라우저에 저장되어 재방문 시 그대로 복원된다. 각 필드가 비어 있으면 0으로 취급한다.
- 예상 근무 제외: 전일(8H) 일수 · 반일(4H) 일수 · 반반일(2H) 일수, 세 개의 고정된 숫자 입력(각각 정수, 0 이상). 목록에 추가·삭제하는 방식이 아니라 각 타입별로 하나씩 직접 입력한다. 브라우저에 저장되어 재방문 시 그대로 복원된다. 비어 있으면 0으로 취급한다.
- 사용자 정의 휴일(팝업 입력): "+ 휴일 추가" 버튼을 누르면 열리는 대화상자에서 이름(문자열, 필수) · 반복 여부(반복 안함/매년 반복 중 하나) · 날짜를 입력한다. 반복 안함이면 연-월-일을 하나의 날짜 입력칸으로 받고, 매년 반복이면 월·일만 각각 숫자로 입력받는다(연도는 저장하지 않음). 이름이 비어 있거나 날짜·월·일이 올바르지 않으면(월 1~12, 일 1~31 범위 정수가 아니면) 대화상자를 닫지 않고 오류 메시지를 표시한다. 추가된 항목은 브라우저에 저장되어 재방문 시 그대로 복원된다.

정상근무시간·누적근무시간·남은 근무 일수는 사용자가 근태 화면에서 직접 읽어 매번 입력한다.

## Calculation and judgment

- 누적근무시간 = 누적근무시간(시간) + 누적근무시간(분) ÷ 60
- 총예상근무시간 = Σ (항목.시간 + 항목.분 ÷ 60) × 항목.일수 (모든 예상 근무 계획 항목 합계)
- 총제외시간 = 전일일수×8 + 반일일수×4 + 반반일일수×2
- 유효목표시간 = 정상근무시간 − 총제외시간
- 예상누적근무시간 = 누적근무시간 + 총예상근무시간
- 판정 (입력값이 바뀔 때마다 자동으로 다시 계산):
  - 예상누적근무시간 > 유효목표시간 → **초과 예상** (초과시간 = 예상누적근무시간 − 유효목표시간)
  - 예상누적근무시간 = 유효목표시간 → **충족 예상**
  - 예상누적근무시간 < 유효목표시간 → **부족 예상** (부족시간 = 유효목표시간 − 예상누적근무시간)
- 총예상근무계획일수 = Σ 예상 근무 계획 항목.일수. 남은 근무 일수 필드가 비어 있지 않고 총예상근무계획일수 > 남은 근무 일수이면, 위 판정과 별개로 경고를 함께 표시한다. 남은 근무 일수가 비어 있으면(0으로 취급되더라도) 이 경고는 계산하지 않는다. 그렇지 않으면 남은 근무 일수를 아직 입력하지 않은 상태에서 예상 근무 계획만 채워도 항상 경고가 뜨게 된다.

### 결과 표시

판정 결과는 상태별로 다른 색이 적용된 카드 안에, 굵은 글씨의 판정 제목과 상세 내용 불릿 목록으로 표시한다. 제안은 이 카드 안의 불릿이 아니라, 카드 바로 아래에 점선 테두리로 구분된 별도 영역에 표시한다.

- 초과 예상: 빨간 계열 카드. 불릿 = [총예상근무시간, 예상 근무 제외, "목표 대비 N시간 초과"]
- 충족 예상: 초록 계열 카드. 불릿 = [총예상근무시간, 예상 근무 제외, "목표를 정확히 채웁니다."] (이미 정확히 맞으므로 제안 없음)
- 부족 예상: 주황/호박(amber) 계열 카드. 불릿 = [총예상근무시간, 예상 근무 제외, "목표 대비 N시간 부족"]
- 입력 오류: 기존과 동일하게 destructive 색상 카드, alert 역할.

### 제안 (별도 영역)

초과 예상 또는 부족 예상일 때만 결과 카드 아래에 별도 영역으로 표시한다(충족 예상·입력 오류에는 표시하지 않는다). 초과시간 또는 부족시간을 "간격시간"이라 하면:

1. 예상 근무 계획 항목 중 일수가 가장 많은 항목을 대상 항목으로 고른다(동률이면 먼저 나오는 항목). 항목이 하나도 없으면 2번으로 간다.
2. 대상 항목의 하루 시간(시간 + 분÷60)이 0보다 크면, 조정일수 = round(간격시간 ÷ 대상 항목의 하루 시간)을 구한다. 조정일수가 0보다 크면 "일수 조정 제안"을 사용한다: 초과 예상이면 새 일수 = max(0, 대상 항목의 일수 − 조정일수), 부족 예상이면 새 일수 = 대상 항목의 일수 + 조정일수. 조정으로 실제로 채워지는 시간이 간격시간과 정확히 같으면 "정확히 맞습니다.", 다르면(반올림으로 어긋남) "목표에 가장 가깝게 맞춰집니다."라고 표시한다.
   - 문구: "제안: N번째 계획(하루 H:MM)의 일수를 A일에서 B일로 조정하면 {정확히 맞습니다.|목표에 가장 가깝게 맞춰집니다.}"
   - 이 문구 아래에 "제안 적용" 버튼이 함께 표시되며, 누르면 그 즉시 대상 항목의 일수 입력값이 새 일수로 바뀌고 결과가 다시 계산된다.
3. 대상 항목이 없거나(1번) 하루 시간이 0이거나 조정일수가 0이면(2번), 일수 조정 제안 대신 기존 방식의 문구로 대체한다(적용 버튼 없음): 초과 예상이면 "제안: 예상 근무 계획을 N시간 줄이면 정확히 맞습니다.", 부족 예상이고 남은 근무 일수가 입력되어 있으면 "제안: 남은 근무 일수 M일 동안 하루 평균 (N÷M)시간씩 계획하면 정확히 맞습니다.", 부족 예상이고 남은 근무 일수가 비어 있으면 "제안: 예상 근무 계획에 N시간을 추가하면 정확히 맞습니다."

## Acceptance criteria

- 화면 상단에 오늘 날짜 기준 이번 정산기간이 "YYYY. M. D ~ YYYY. M. D" 형식(매월 20일~익월 19일)으로 표시된다.
- "계산하기" 버튼은 없으며, 정상근무시간·누적근무시간·남은 근무 일수·예상 근무 계획·예상 근무 제외 중 어느 값이든 바뀌면 결과가 자동으로 다시 계산되어 표시된다.
- "+ 추가"를 누르면 시간·분·일수를 입력할 수 있는 예상 근무 계획 항목이 새로 나타난다.
- 예상 근무 계획 항목이 여러 개일 때 각 항목을 개별적으로 삭제할 수 있다.
- "예상 근무 제외"에는 전일(8H)·반일(4H)·반반일(2H) 입력칸이 각각 하나씩 항상 표시되며, 추가·삭제 버튼은 없다.
- "예상 근무 계획" 제목 옆에 그 시점까지 입력된 항목들의 총예상근무시간이 "총 H:MM" 형식(예: 17:00, 1:45)으로, 그 옆에 총 일수(모든 항목의 일수 합계)가 "N일" 형식으로 함께 표시되며(예: "총 17:00 · 2일"), 값이 바뀔 때마다 갱신된다.
- "예상 근무 제외" 제목 옆에 전일·반일·반반일 값을 반영한 총제외시간이 "총 N시간" 형식으로 표시되며, 값이 바뀔 때마다 갱신된다.
- 페이지를 새로 열면 남은 근무 일수 입력칸에 오늘 날짜 기준으로 근태일정 종료일까지, 공휴일·토요일·일요일을 제외한 근무 일수가 자동으로 채워져 있다.
- 아무 값도 입력하지 않은 초기 상태(모든 필드가 비어 있음)에서도 오류 없이 "충족 예상"이 표시된다(모든 값이 0으로 취급되어 0 = 0).
- 예상누적근무시간이 유효목표시간(정상근무시간 − 총제외시간)보다 크면 "초과 예상" 판정과 초과 시간이 표시된다.
- 예상누적근무시간이 유효목표시간과 같으면 "충족 예상" 판정이 표시된다.
- 예상누적근무시간이 유효목표시간보다 작으면 "부족 예상" 판정과 부족 시간이 표시된다.
- 판정 결과는 상태(초과 예상=빨강, 충족 예상=초록, 부족 예상=주황/호박, 입력 오류=destructive)별로 시각적으로 구분되는 색상 카드에, 굵은 판정 제목과 불릿(목록) 형태의 상세 내용으로 표시된다.
- 제안은 결과 카드 안의 불릿이 아니라, 카드 바로 아래의 별도 영역에 표시된다. 충족 예상·입력 오류일 때는 이 영역이 표시되지 않는다.
- 예상 근무 계획 항목 중 일수가 가장 많은 항목의 하루 시간이 0보다 크고, 초과·부족 시간을 그 하루 시간으로 나눠 반올림한 조정일수가 0보다 크면, "N번째 계획(하루 H:MM)의 일수를 A일에서 B일로 조정하면…"이라는 일수 조정 제안과 "제안 적용" 버튼이 함께 표시된다. 버튼을 누르면 그 즉시 해당 항목의 일수 입력값이 제안된 값으로 바뀌고 결과가 다시 계산된다.
- 예상 근무 계획 항목이 여러 개이면, 그중 일수가 가장 많은 항목을 대상으로 일수 조정 제안이 만들어진다.
- 일수 조정으로 채워지는 시간이 초과·부족 시간과 정확히 같으면 "정확히 맞습니다"라고 표시되고, 반올림으로 어긋나면 "목표에 가장 가깝게 맞춰집니다"라고 표시된다.
- 일수 조정 제안을 만들 수 없을 때(대상 항목이 없거나, 하루 시간이 0이거나, 조정일수가 0으로 반올림될 때)는 적용 버튼 없이 기존 방식의 문구로 대체된다: 초과 예상이면 "예상 근무 계획을 N시간 줄이면 정확히 맞습니다", 부족 예상이고 남은 근무 일수가 입력되어 있으면 "남은 근무 일수 M일 동안 하루 평균 X시간씩 계획하면 정확히 맞습니다", 남은 근무 일수가 비어 있으면 "예상 근무 계획에 N시간을 추가하면 정확히 맞습니다".
- 정상근무시간·누적근무시간(시간·분)·남은 근무 일수·예상 근무 계획의 각 필드·예상 근무 제외의 각 필드 중 하나라도 음수이거나 정수여야 하는데 소수를 입력하면(해당하는 경우), 계산 결과 대신 오류 메시지가 alert로 표시된다. 반대로 어떤 필드든 비워두면 오류가 아니라 0으로 취급되어 계산이 계속된다.
- 남은 근무 일수를 입력했을 때, 예상 근무 계획의 총 일수가 남은 근무 일수보다 많으면 그 사실을 알리는 경고가 함께 표시된다. 남은 근무 일수를 비워두면 예상 근무 계획을 얼마나 채웠든 이 경고가 표시되지 않는다.
- 예상 근무 계획 항목과 예상 근무 제외 값을 입력·수정한 뒤 웹페이지를 다시 불러오면, 마지막 상태 그대로 복원되어 채워져 있다.
- 정상근무시간·누적근무시간·남은 근무 일수는 저장되지 않으며, 웹페이지를 다시 불러오면 빈 값으로 시작한다.
- 화면 하단에 상단의 근태일정 기간 내에 있는 대한민국 공휴일 목록이 "근태일 기준 공휴일"이라는 제목으로 표시된다. 그 기간에 공휴일이 없으면 그 사실을 알 수 있게 표시한다(빈 목록으로 방치하지 않음).
- "근태일 기준 공휴일" 제목 옆(또는 근처)의 "+ 휴일 추가" 버튼을 누르면 이름·반복 여부·날짜를 입력하는 대화상자(팝업)가 열린다.
- 대화상자에서 이름과 날짜(반복 안함) 또는 이름과 월·일(매년 반복)을 입력하고 "추가"를 누르면 대화상자가 닫히고, 그 항목이 근태일정 기간 안에 있으면 "근태일 기준 공휴일" 목록에 즉시 나타난다.
- 이름을 비워두거나 날짜(반복 안함) 또는 월·일(매년 반복)에 올바르지 않은 값을 입력하고 "추가"를 누르면 대화상자가 닫히지 않고 오류 메시지가 표시된다.
- 매년 반복으로 추가한 휴일은 근태일정 기간이 걸쳐 있는 모든 해에 대해 해당 월·일이 기간 안에 있으면 목록에 나타난다(예: 12월~1월에 걸친 정산기간이면 다음 해 1월의 매년 반복 휴일도 포함).
- 사용자가 추가한 휴일은 대한민국 공휴일과 함께 날짜순으로 병합되어 "근태일 기준 공휴일" 목록에 표시된다.
- 사용자가 추가한 휴일 항목에만 "삭제" 버튼이 표시되며, 눌러 지우면 해당 항목만 목록에서 사라진다. 대한민국 공휴일 항목에는 삭제 버튼이 없다.
- 사용자가 추가한 휴일은 브라우저에 저장되어, 웹페이지를 다시 불러와도 "근태일 기준 공휴일" 목록에 그대로 남아 있다.

## Settled constraints and rationale

- 남은근무일수 단일 숫자 대신 예상 근무 계획(여러 항목)을 쓰는 이유: 사용자가 실제로 어떻게 일할지 시간·분 단위로 구체적으로 계획하면, "하루 평균 얼마나 일해야 하는지" 추천하는 것보다 그 계획이 목표를 채우는지 직접 판정하는 것이 더 정확하다. (사용자가 "대체로 진행"을 직접 확정함.)
- "남은 근무 일수"를 다시 추가하되 계산의 직접 입력이 아니라 예상 근무 계획 총 일수 대비 경고 용도로 한정한 이유: 시간 기준 판정(초과/충족/부족 예상) 로직은 이미 정리되어 있어 다시 바꾸지 않고, 계획이 실제로 남은 일수 안에 들어가는지 점검하는 보조 정보로만 추가하기로 사용자가 확정함.
- 예상 근무 제외가 "정상근무시간(목표)"을 차감하는 방식인 이유: PRODUCT.md의 원래 정의(정상근무시간 = (근무일수 − 휴일 − 휴가일수) × 8시간)에 따르면 휴가는 목표 자체를 줄이는 항목이다. (사용자가 직접 확정함.)
- 예상 근무 제외를 목록형 추가·삭제 대신 전일/반일/반반일 고정 3칸으로 바꾼 이유: 타입이 세 가지로 고정돼 있어 목록으로 관리할 필요가 없고, 사용자가 직접 더 단순한 입력 방식을 요청함.
- 누적근무시간을 시간·분 두 필드로 나눈 이유: 실제 근태 화면이 "8시간 0분"처럼 시간·분을 따로 보여주므로, 사용자가 화면에서 본 값을 그대로 옮겨 적을 수 있게 함(사용자가 직접 요청함).
- 필드 라벨에 단위를 덧붙인 이유(정상근무시간(시간), 남은 근무 일수(일), 전일(8H) 등): 어떤 단위로 입력해야 하는지 명확히 보이도록 사용자가 직접 요청함.
- 빈 입력을 오류가 아니라 0으로 취급하도록 바꾼 이유: "계산하기" 버튼을 없애고 입력 즉시 자동으로 계산하게 되면서, 아직 다 채우지 않은 중간 상태에서도 오류 없이 결과를 보여줘야 자연스럽다. 사용자가 직접 이 순서(제외 값 없어도 계산, 빈 값은 0, 버튼 제거)로 요청함.
- 계산 버튼을 없애고 자동 계산으로 바꾼 이유: 값이 바뀔 때마다 즉시 결과를 보고 싶다는 사용자 요청. 결과는 입력 상태로부터 매번 다시 계산하는 파생값이라 별도 상태나 버튼 없이도 항상 최신 상태를 보여줄 수 있다.
- 결과를 판정별 색상 카드 + 굵은 제목 + 불릿 목록으로 바꾼 이유: 한 문장으로 길게 서술하던 결과를 더 눈에 띄고 읽기 쉽게 만들어달라는 사용자 요청. 색상은 프로젝트에 정의된 디자인 토큰 중 상태별 의미(초과=위험, 충족=성공, 부족=주의)에 맞는 별도 토큰이 없어 Tailwind의 red/green/amber 계열을 라이트·다크 모드 모두 고려해 직접 사용했다.
- "정상근무시간에 딱 맞게" 조정 제안을 추가한 이유: 초과/부족 판정만 보여주는 데 그치지 않고, 목표에 정확히 맞추려면 예상 근무 계획을 얼마나 조정해야 하는지까지 알려달라는 사용자 요청. 남은 근무 일수가 있으면 하루 평균으로, 없으면 총량으로 제안한다.
- 제안을 결과 카드의 불릿에서 분리해 별도 영역으로 뺀 이유: 판정 결과(총예상근무시간·초과·부족 등 사실)와 제안(앞으로 어떻게 할지에 대한 권고)은 성격이 다르므로 구분해서 보여달라는 사용자 요청.
- 제안을 "N시간을 줄이거나 늘리라"는 시간 단위 문구 대신 예상 근무 계획의 특정 항목의 일수를 조정하라는 문구로 바꾸고 "제안 적용" 버튼을 추가한 이유: 사용자가 실제로 입력해 둔 계획(항목별 하루 시간·일수)을 기준으로, 어떤 항목의 일수를 얼마로 바꾸면 되는지 구체적으로 알려주고 한 번에 반영할 수 있게 해달라는 요청. 조정 대상은 여러 항목 중 일수가 가장 많은 항목(가장 대표적인 근무 패턴으로 간주)으로 사용자가 직접 확정했고, 그 항목의 하루 시간으로 나눈 조정일수는 정확히 나누어지지 않으면 가장 가까운 정수로 반올림하기로 사용자가 직접 확정했다(반올림으로 목표에 정확히 맞지 않을 수 있음을 감수).
- "예상 근무 계획" 제목 옆 총예상근무시간에 총 일수를 함께 표시한 이유: 총 시간만 보고는 지금까지 입력한 계획이 며칠 치인지 바로 알 수 없어, 사용자가 남은 근무 일수·총 일수 경고와 비교하기 편하도록 총 시간 옆에 총 일수를 나란히 보여달라는 사용자 요청.
- 일수 조정 제안을 만들 수 없는 경우(예상 근무 계획 항목이 없거나, 대상 항목의 하루 시간이 0이거나, 조정일수가 0으로 반올림되는 경우) 기존의 시간 단위 문구로 대체하기로 한 이유: 이런 경우는 일수를 조정해도 의미 있는 변화를 제안할 수 없으므로(예: 조정일수가 0으로 반올림되면 "0일 조정"은 제안이 아니다), 이미 검증되어 있던 기존 문구를 그대로 안전망으로 남겨 항상 어떤 제안이든 보여주도록 했다.
- 공휴일 표시·근태일정 표시를 계산에 관여하지 않는 순수 참고 정보로 한정한 이유: "앱이 캘린더/공휴일 로직을 갖지 않는다"는 기존 결정을 완전히 뒤집지 않으면서, 사용자가 예상 근무 제외 값을 정하거나 정산기간을 파악할 때 참고할 수 있게만 좁게 예외를 둔다.
- 공휴일 표시 범위를 "이번 달"에서 "근태일정 기간"으로 바꾼 이유: 정산기간이 두 달에 걸치므로(예: 8/20~9/19), 달력 월 기준보다 실제 근태일정 기준이 사용자가 참고하기에 더 적합하다고 판단함(사용자가 직접 확정함).
- 근태 화면 캡처 업로드 자동 인식을 다시 제외한 이유: 서버 API + Claude(vision) 연동으로 한 차례 구현했으나, 로컬에 API 키가 없어 실제 동작을 검증할 수 없었다. API 키 없이 가능한 대안(클라이언트 OCR 등)을 검토하는 대신, 사용자가 이 기능 자체를 범위에서 빼기로 결정함.
- 예상 근무 계획·예상 근무 제외만 저장하고 정상근무시간·누적근무시간·남은 근무 일수는 저장하지 않는 이유: 세 값은 매번 근태 화면에서 새로 확인해 입력하는 값이라 저장 대상에서 제외했다.
- 로그인/서버 저장을 다루지 않는 이유: PRODUCT.md에도 인증 방식은 Unknown으로 남아 있고, 이번 범위는 브라우저 로컬 저장으로 충분하다.
- 남은 근무 일수를 오늘 날짜·근태일정·공휴일 데이터로 자동 계산해 기본값으로 채우는 이유: 사용자가 직접 달력을 세지 않아도 되도록 요청함. 이미 검증된 공휴일 데이터(getHolidaysInRange)와 정산기간 계산을 재사용해 주말·공휴일을 제외한 일수를 계산하며, 자동으로 채워진 값도 사용자가 필요하면 직접 수정할 수 있다.
- 예상 근무 계획·예상 근무 제외 제목 옆에 합계를 표시하는 이유: 항목을 추가·수정하는 중에 지금까지 합계가 얼마인지 바로 확인할 수 있게 해달라는 사용자 요청. 예상 근무 계획은 분 단위가 섞여 있어 시간:분(예: 17:00) 형식으로, 예상 근무 제외는 항상 정수 시간이라 "N시간"으로 표시한다.
- 사용자 정의 휴일을 추가할 수 있게 한 이유: 근태일 기준 공휴일 목록이 대한민국 공휴일만 담고 있어 회사 자체 휴무일(창립기념일 등)을 반영하지 못한다는 한계를 사용자가 직접 지적함.
- 버튼을 누르면 팝업(대화상자)이 열리는 방식을 쓴 이유: 사용자가 직접 이 상호작용 방식을 요청함. 목록 화면에 입력칸을 상시 노출하는 대신, 추가할 때만 대화상자로 이름·반복 여부·날짜를 한 번에 입력받아 목록을 간결하게 유지한다.
- 반복 옵션을 "반복 안함"과 "매년 반복" 두 가지로 한정한 이유: 회사 휴무일 대부분이 1회성 또는 매년 같은 월·일에 반복되는 성격이라 이 두 옵션으로 충분하다고 판단했고, 사용자가 이 범위를 직접 확정함("응, 그렇게 진행해줘"). 매주 반복·매월 반복 등은 다루지 않는다.
- "매년 반복" 휴일에 연도를 저장하지 않는 이유: 반복의 의미가 "해마다 같은 월·일"이므로 특정 연도에 종속되지 않는다. 근태일정 기간이 걸친 모든 해에 대해 월·일만으로 판정한다.
- 사용자가 추가한 휴일에만 삭제 버튼을 두고 대한민국 공휴일에는 두지 않은 이유: 대한민국 공휴일은 앱에 내장된 고정 데이터라 사용자가 개별적으로 지울 수 있는 대상이 아니다.
- 사용자가 추가한 휴일을 대한민국 공휴일과 병합해 하나의 목록으로 표시하는 이유: "근태일 기준 공휴일"이 근무 제외를 판단할 때 참고하는 하나의 통합된 참고 목록이라는 기존 취지를 유지하기 위해, 출처가 다르다는 이유로 목록을 분리하지 않는다.

## Assumptions

- 분(分) 값이 59를 넘어도(예: 90분) 시간으로 환산해 계산한다(90분 = 1.5시간); 별도 범위 제한은 두지 않는다.
- 저장은 브라우저의 localStorage를 사용하며, 로그인·계정 없이 이 브라우저에만 남는다. 프라이빗 모드 등 localStorage를 사용할 수 없는 환경은 다루지 않는다.
- 근무일수는 정수, 근무시간(정상근무시간·누적근무시간)은 소수점을 허용한다.
- 총제외시간이 정상근무시간보다 커서 유효목표시간이 음수가 되는 경우도 그대로 계산한다(별도 하한 없음).
- 공휴일 데이터는 몇 해 분량(2025~2027)만 앱에 내장된 정적 목록이며, 그 기간이 지나면 목록을 갱신해야 한다.
- 사용자 정의 휴일의 날짜·월·일은 형식(정수 범위)만 검증하며, 실제 달력상 존재하는 날짜인지(예: 2월 30일, 4월 31일)는 검증하지 않는다.
- 사용자 정의 휴일의 id는 세션 내 카운터로 생성하며, 전역적으로 고유함을 보장하는 별도 체계(UUID 등)를 쓰지 않는다.

## Off-limits (excluded, with reason)

- 근태 화면 캡처 업로드·자동 인식: 사용자가 이 기능 자체를 범위에서 빼기로 결정함. 필요해지면 별도 스펙에서 다시 다룬다.
- attendance.lge.com 자동 접속·연동: 실시간 로그인·자동화는 이번 범위 밖이다.
- 로그인/인증, 서버 측 사용자별 데이터 저장: 이번 결과 검증에 불필요하다.
- 공휴일 데이터를 이용한 정상근무시간·유효목표시간 자동 계산: 공휴일 데이터는 남은 근무 일수의 기본값 계산에만 쓰이며, 정상근무시간이나 유효목표시간 자체를 자동으로 채우지는 않는다(그 값들은 여전히 사용자가 근태 화면을 보고 직접 입력한다).

## Deferred points

- 전 직원 대상 서비스로서의 인증·서버 측 개인별 데이터 보관 방식
- 근태 화면 캡처 업로드 자동 인식 — 다시 다룬다면 API 키 없이도 동작하는 방식(예: 클라이언트 OCR)을 포함해 별도로 재검토한다.

## Remaining risks

- 예상 근무 계획·예상 근무 제외는 어디까지나 "계획"이며, 실제로 그렇게 진행했는지는 이 도구가 검증하지 않는다.
- 브라우저의 localStorage가 지워지거나(캐시 삭제 등) 다른 브라우저/기기로 접속하면 저장된 값이 보이지 않는다.
- 공휴일 정적 목록이 담고 있는 기간(2025~2027)을 벗어나면 근태일 기준 공휴일이 표시되지 않거나 갱신이 필요하다.
- 빈 입력을 0으로 취급하므로, 사용자가 값을 아직 다 입력하지 않은 중간 상태에서도 그럴듯한(하지만 완성되지 않은) 결과가 항상 표시된다 — 다 입력했는지 여부를 구분해서 알려주지 않는다.
- 남은 근무 일수의 자동 계산 기본값은 근태일정·공휴일 표시와 마찬가지로 렌더링 시점에 `new Date()`를 사용한다. 서버 렌더링과 클라이언트 하이드레이션 사이에 날짜가 걸쳐 있으면(자정 근처, 시간대 차이 등) 하이드레이션 불일치가 생길 수 있다는 기존 리스크를 이 필드도 동일하게 가진다.
- 사용자가 추가하는 휴일 개수에 상한이 없어, 계속 추가하면 "근태일 기준 공휴일" 목록이 끝없이 길어질 수 있다.
- 사용자가 추가한 휴일과 대한민국 공휴일이 같은 날짜를 가리켜도 중복 여부를 확인하거나 병합하지 않고 각각 별도 항목으로 표시한다.
